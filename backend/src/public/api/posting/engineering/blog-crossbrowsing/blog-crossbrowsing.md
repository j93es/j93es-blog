## 0. 들어가며

어플리케이션을 여러 브라우저 환경에서 잘 실행되게 하는 것이 크로스 브라우징입니다. 특정 브라우저에서 어플리케이션이 동작하지 않는다면, 사용자는 해당 웹사이트에 대한 신뢰를 잃을 수 있습니다. 즉, 사용자 경험이나 웹사이트의 신뢰에 있어, 크로스 브라우징은 중요한 요소 중 하나일 것입니다.

각각의 사용자는 다양한 OS나 브라우저를 사용하기도 합니다. 그런데 브라우저마다 동작 방식이 미묘하게 상이한 경우가 있습니다. 예를 들어 CSR 어플리케이션의 경우, 사파리와 크롬의 브라우저 히스토리 저장 방식에 차이가 있기도 합니다. 더하여 구형 네이버 앱의 경우 에러 처리 방식에서 타 브라우저와 차이가 있기도 합니다. 또한 OS마다 기본적으로 지원하는 폰트에 차이가 있기도 합니다. 더하여 기본 margin에 차이가 있는 등, CSS가 다르게 적용되기도 합니다. 여기에서 우리는 한가지 개선점을 찾아볼 수 있습니다. 사용자가 OS/브라우저 변경시에 위화감을 느끼지 않도록, OS/브라우저에 관계없이 사용자에게 일관된 경험을 제시하는 것이 하나의 개선점일 수 있겠네요.

더하여 구형 OS를 사용하기도 하며, 이에 따라 구형 브라우저를 사용하기도 합니다. 그런데 HTML이나 CSS의 특정 기능은 구형 브라우저에서 지원되지 않기도 합니다. 즉, 구형 브라우저를 활용하는 사용자를 고려하여 어플리케이션을 제작하는 것이 필요한 경우가 있습니다.

지금부터는 OS/브라우저에 관계없이 사용자에게 일관된 경험을 제시하고, 구형 브라우저 호환성을 유지하는 것이 목적인 크로스 브라우징에 대하여 살펴보겠습니다.

## 1. 네이버 앱 오류 해결

크로스 브라우징을 테스트할 때에, 브라우저의 다양한 기능을 이용해보고 정상 작동하는지 테스트하는 경우는 드물 수 있다고 생각합니다. 보통 해당 브라우저에서 어플리케이션이 잘 랜더링되는지 등을 테스트하죠. 그런데 브라우저 자체의 기능을 이용하고 잘 동작하는지 확인하는 것 또한 중요하다고 생각합니다.

안드로이드 네이버 앱의 경우 웹사이트 공유하기 기능이 존재합니다. 그런데 2025년 2월 1일 기준, 에러 핸들링을 할때에 `onerror` 이벤트 리스너 등록시, 공유하기 버튼을 누른다면 에러가 발생하여 정상적으로 어플리케이션이 동작하지 않았습니다. 더하여 동일한 현상이 개인정보보호 브라우징에서도 발생하였습니다.

즉, 크로스 브라우징을 고려할때, 랜더링이 잘 되는지 테스트해보는 것 뿐만 아니라, 브라우저의 기능(ex. 개인정보보호 브라우징, 공유하기 버튼) 등을 이용했을때, 정상적으로 작동하는지 확인해보는 것이 중요하다고 생각합니다.

## 2. Safari 트랙패드 이슈

Safari 브라우저에서 트랙패드로 뒤로가기 제스처 시에 브라우저가 1초간 멈추는 이슈가 있었습니다. 이슈가 발생했다면, 그 이유를 파악해야겠죠. [링크](https://bugs.webkit.org/show_bug.cgi?id=248303)에서 비슷한 이슈를 겪고 있는 사용자가 있었습니다. 해당 링크를 근거로 간단히 설명해보겠습니다. 브라우저는 뒤로가기 시에, 히스토리에 항목을 추가합니다. 이때, 짧은 터치 제스처(touchstart → touchend가 빠르게 실행됨)는 히스토리 항목이 정상적으로 추가되지만(뒤로 가기 버튼이 동작함), 긴 터치 제스처(touchstart 후 1초 이상 대기 후 touchend)는 히스토리 항목이 사용자 상호작용으로 추가된 것으로 간주되지 않기 때문인 것으로 추측합니다.(뒤로 가기 버튼이 작동하지 않음). 

이를 어떻게 해결해야할까요? 브라우저 히스토리가 변경되려한다면, popstate라는 이벤트가 발생합니다. 즉, popstate 이벤트가 발생하면, `window.location.reload();`하여 1초 동안 창이 멈추는 이슈를 해결하였습니다.

## 3. 페이지 뒤로가기 시에 뷰포인트 조정

여러번 뒤로가기 시에, 페이지마다 뷰포인트가 위 아래로 변화한다면 깔끔하지 않은 웹사이트라는 인상을 주진 않을까요? 먼저 상황을 가정해보겠습니다. 1번째 포스팅을 전부 읽어서 뷰포인트가 제일 아래까지 내려왔습니다. 다음 2번째 포스팅 버튼을 클릭 후, 해당 포스팅도 전부 읽었습니다. 2번째 포스팅도 전부 읽어서, 뷰포인트가 제일 마지막까지 내려왔습니다. 그리고 3번째 포스팅에 접근하였습니다. 즉, 브라우저 히스토리에 3개의 페이지가 저장되었습니다. 

이때, 페이지 뒤로가기 버튼을 2번 누른다면, 뷰포인트는 전부 아래로 고정될까요? 아닙니다. 브라우저마다 히스토리가 저장되는 방식이 다릅니다. 더하여 CSR의 경우 이러한 특성이 두드러진다고 판단합니다.(사파리의 경우 여러번 뒤로가기 시에, 랜더링 된 후를 히스토리에 저장하는 경우와 path만을 히스토리에 남기는 경우가 섞여있는 경우도 있더군요.) 제가 블로그를 개발할 당시 특정 브라우저의 경우 2번 뒤로가기 시에, 특정 페이지는 뷰포인트가 위로 로드되기도, 특정 페이지는 뷰 포인트가 아래로 로드되기도 했었습니다. 이때 뒤로가기 시에 브라우저마다 뷰포인트가 다르게 노출되는 것이 사용자 경험에 좋을까요? 저는 일관된 사용자 경험을 위해서는 뒤로가기 시에 뷰포인트가 위로 고정되는 것이 깔끔한 인상을 줄 수 있다고 판단하였습니다.

따라서 다음의 코드를 통하여 path가 변하거나, 로딩이 끝난 후에 페이지의 뷰포인트를 상단으로 고정하였습니다.

```tsx
// React
import { useEffect } from "react";

// External
import { useLocation } from "react-router-dom";

// Local
import { useLoading } from "contexts/LoadingProvider";

const useScrollToTop = () => {
  const { pathname } = useLocation();
  const { isLoading } = useLoading();

  useEffect(() => {
    window.scrollTo(0, 0);
  }, [pathname]);

  useEffect(() => {
    if (!isLoading) {
      window.scrollTo(0, 0);
    }
  }, [isLoading]);
};
```

## 4. 폰트

React 어플리케이션의 경우 body 태그에 다음과 같이 폰트를 지정하기도 합니다.

```css
body {
  font-family: -apple-system, BlinkMacSystemFont, system-ui, Roboto,
    "Helvetica Neue", "Segoe UI", "Apple SD Gothic Neo", "Noto Sans KR",
    "Malgun Gothic", "Apple Color Emoji", "Segoe UI Emoji", "Segoe UI Symbol",
    sans-serif;
}
```

그런데 이렇게 폰트를 지정하는 것이 여러 OS에서 일관된 경험을 제공할 수 있을까요? 사용자나 OS가 기본으로 셋팅한 폰트를 그대로 사용한다면, 어플리케이션이 UI 설계에서 의도했던 느낌이 아닌, 전혀 다른 느낌의 디자인으로 바뀔 수 있습니다. 즉, 어플리케이션의 UI에 적합한 폰트를 다양한 OS에 일관되게 적용하는 것이 중요합니다.

## 5. normalize.css, reset.css

브라우저마다 기본 margin이나 padding 등 CSS 요소의 기본 적용값이 다릅니다. 즉, 브라우저마다 동일한 UI 경험을 위해서는 CSS를 정규화하거나 초기화하는 것이 필요합니다.

CSS를 정규화하는 것은 브라우저가 가진 유용한 기본 디자인을 없애지 않는 선에서, CSS 요소의 일관성을 유지하는 것입니다. 즉,  브라우저 기본 스타일을 살리면서 서로 다른 점만 보기 좋게 맞추는 것입니다. normalize.css라는 파일을 다운 받아서, root에 해당하는 CSS에 적용하는 것이 대표적인 적용방식입니다.

CSS를 초기화하는 것은, CSS의 모든 여백(margin, padding)과 글자 크기 설정을 0으로 완전히 지우는 것으로, CSS 요소의 일관성을 유지하는 것입니다. 이는 다시말해, CSS의 여백이나 글자 크기 설정을 다시 지정해줘야한다는 점입니다. 이는 reset.css를 많이들 적용하는 것으로 압니다.

이처럼 브라우저마다 다른 CSS의 기본값의 일관성을 유지하는 방법을 살펴보았습니다.

## 6. 구형 브라우저 호환

구형 브라우저의 경우, 최신 웹 기능을 지원하지 않는 경우가 있습니다. 대표적으로 3가지 케이스가 있습니다. 

첫째로 html5 태그를 지원하지 않는 경우가 있다는 것입니다. html5 태그에는 header, nav, section 등이 있습니다. 상당히 많이 활용되는 태그임에도 불구하고 구형브라우저에서는 이러한 태그를 지원하지 않는 경우가 많습니다. 

둘째로, CSS 변수를 이용하지 못하는 경우가 있습니다. CSS 변수는 다음과 같이 사용합니다.

```css
:root {
  --main-color: #3498db;
  --padding-size: 10px;
}

body {
  background-color: var(--main-color);
  padding: var(--padding-size);
}
```

CSS의 유지보수성을 높혀주는 CSS 변수를 구형브라우저에서는 사용하지 못하는 경우가 있습니다.

셋째로, CSS 가상 선택자를 지원하지 않는 경우가 있습니다. 웹사이트에서 마우스를 올리면 요소가 커지거나 작아지는 경우가 있습니다. 이러한 기능을 구현할때, `:hover`라는 CSS 가상 선택자를 사용합니다. 이 외에도 여러 CSS 가상 선택자가 존재합니다. 위의 경우와 마찬가지로 구형 브라우저에서 이러한 CSS 기능을 지원하지 않는 경우가 있습니다.

이러한 기능을 구형브라우저에 완전히 호환시키진 못하더라도, 대안이 될 수 있는 방법이 있습니다. 바로 아래의 polyfill 코드를 사용하는 것입니다.

```tsx
const useCrossBrowsingPoliyfill = () => {
  useEffect(() => {
    const isCssVariablesNotSupported =
      !window.CSS ||
      !window.CSS.supports ||
      !window.CSS.supports("--custom-prop", "1");

    const isCssViSelectorNotSupported =
      !window.CSS ||
      !window.CSS.supports ||
      !window.CSS.supports("selector(:nth-child(1))") ||
      !window.CSS.supports("selector(:not(.class))");

    const html5Elem = document.createElement("nav");
    const isHTML5NotSupported = html5Elem instanceof HTMLUnknownElement;

    // css 변수 크로스 브라우징
    if (isCssVariablesNotSupported) {
      import("css-vars-ponyfill")
        .then((module) => {
          const cssVars = module.default;
          cssVars({ watch: true, onlyLegacy: true });
        })
        .catch((err) => {});
    }

    // css3 가상 선택자 크로스 브라우징
    if (isCssViSelectorNotSupported) {
      import("selectivizr");
    }

    // html5 크로스 브라우징
    if (isHTML5NotSupported) {
      import("html5shiv");
    }
  }, []);
};
```

이때 살짝의 디테일을 설명해보겠습니다. 총 3개의 라이브러리가 존재합니다. 각각 html5 태그, CSS 변수, CSS 가상 선택자와 관련이 있습니다. 이때 브라우저에서 해당 기능을 지원한다면, 굳이 리소스를 다운받을 필요가 있을까요? 없을 것입니다. 따라서 초기 랜더링 시에 브라우저가 최신 기능을 지원하는지 확인하고, 해당 모듈을 import 하는 방식으로 dynamic import를 적용하였습니다.

## 7. 나오며

지금까지 웹 어플리케이션이 여러 브라우저에서 안정되고 일관되게 동작하도록하는 크로스 브라우징을 살펴보았습니다. 먼저, 특정 브라우저에서만 발생하는 이슈를 해결한 경험을 소개하였습니다. 둘째로, 디자인 요소의 일관성을 유지하는 방법을 살펴보았습니다. 셋째로, 최신 웹 기술을 구형 브라우저에 polyfill하는 방법을 살펴보았습니다.
